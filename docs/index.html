Hidden S3
Encrypted self-hosted S3-compatible object storage for sensitive data on privately managed infrastructure.
The storage is designed to resist unauthorized filesystem access, including hardware loss or theft. Even if encrypted data is obtained from disk, the original contents cannot be recovered without the secret and master password.

S3 versus beyond S3
Encryption is not just about how data is protected, but where protection begins and what it covers.
Standard S3 encryption
Hidden S3 encryption
Encryption is performed by the S3 service as objects are written to storage.
Encryption is performed below the S3 service as files are written to the underlying filesystem.
Object contents are encrypted, while filenames, metadata, IAM data, and internal service data may require separate protection.
Object contents, filenames, metadata stored in files, IAM data, and internal service data are protected by the same encrypted filesystem.
Encryption and key management depend on the capabilities and configuration of the S3 service.
Encryption and key management operate independently of the S3 service through gocryptfs.
Access to encrypted objects generally depends on the S3 service or compatible decryption mechanisms.
The encrypted filesystem can be mounted directly with gocryptfs, allowing access to stored files without the S3 gateway.
The underlying architecture
Data stays encrypted on external volumes. The container hides the decrypted mountpoint and exposes storage and management interfaces.
The mechanics of protection
Data remains encrypted at rest and is accessible only while the storage is mounted. When no longer needed, the storage is unmounted again.
Detachable
secret
The secret is stored encrypted on a separate volume, which can be located on removable media or a remote host. Without it, the storage is unmounted.
Master
password
The master password protects the secret and is never stored by the app. Its validity is verified each time by attempting to decrypt the secret.
Auto
unmount
The storage supports manual unmounting and automatically unmounts if the secret becomes unavailable or the app restarts.
No background transmissions
The app keeps your data on your trusted infrastructure, without AI integrations, telemetry, or unexpected outbound communication.
No AI
access
There are no AI integrations or connections to related platforms. Your files are never shared with remote AI services for analysis or processing.
No silent
reporting
No telemetry, usage statistics, or diagnostics are shared with the project maintainers. The app does not silently transmit any operational information.
The technologies behind the app
The app is based on three open-source technologies that provide S3 object storage, transparent filesystem encryption, and secure lifecycle management.
The S3 API manages objects that are mapped to files through the underlying filesystem backend.
The POSIX backend operates inside a mounted FUSE filesystem, where all data is transparently encrypted.
The REST API controls the encrypted filesystem lifecycle, including initialization, mounting, and unmounting.
Data without vendor lock-in
All data is stored across two volumes, allowing the storage to be restored or mounted independently using gocryptfs.
Secrets
volume
The secrets volume stores the encrypted secret and other security-related data. The secret cannot be decrypted without the master password. This volume should be kept separate from the encrypted storage and connected only when needed.
Cipherdir
volume
The cipherdir volume contains encrypted data and can be safely backed up. In an emergency, it can be mounted directly with gocryptfs, without the app, providing access to files through a standard POSIX filesystem.
Control, access, and management
The app exposes three interfaces for working with storage, from automated integrations and command-line operations to everyday management through a web browser.
REST API
Manage encrypted storage through a REST API, including initialization, mounting, unmounting, and health checks.
S3 API
Access buckets and objects using standard S3-compatible clients, with support for multipart uploads and versioning.
WebGUI
Manage buckets, objects, and user permissions through a browser-based interface without using command-line tools.
